# 08 · 原生层与桥接模块

> 本章讲 `ios/` 与 JS 侧的原生封装（`src/utils/nativeModules/`、`src/utils/fs.ios.ts` 等）。先给全局图景：**原生能力的宿主是一个 6705 行的 `AppDelegate.mm`**，里面内嵌了 11 个桥接模块；另有独立的 Swift 上传模块、vendored 的 libFLAC 与 LiquidGlassKit。JS 侧每个原生模块都有一层带降级的 TS 封装，业务代码不直接摸 `NativeModules`。

---

## 8.1 iOS 工程结构（`ios/`，145 个文件）

```
ios/
├─ LxMusicMobile/
│  ├─ AppDelegate.h / AppDelegate.mm   宿主：11 个内嵌模块 + SceneDelegate + DSP（见 8.2）
│  ├─ main.m                           标准 UIApplicationMain 入口
│  ├─ WebDAVUploadModule.swift / .mm   WebDAV 流式上传（Swift + ObjC 桥）
│  ├─ LXEmbeddedMetadataHelpers.mm     被 #include 进 AppDelegate.mm 的标签读写实现
│  ├─ LXSharedIRConvolutionKernel.hpp  C++ 分区 FFT 卷积内核（纯头）
│  ├─ user-api-preload.js              用户脚本沙箱的注入脚本（打进 Resources）
│  ├─ Info.plist / *.entitlements      配置（entitlements 为空 dict，见 8.5）
│  ├─ LaunchScreen.storyboard / Images.xcassets / icomoon.ttf
├─ Vendor/
│  ├─ LXLibFLAC/                       libFLAC 1.5.0 vendored 源码
│  ├─ LiquidGlassKit/                  液态玻璃 Kit 的本地 pod 化移植（07 章）
│  └─ SwiftAudioEx.podspec.json        本地锁定 podspec（避 trunk CDN 间歇 400）
├─ Podfile                             见 09 章
└─ LxMusicMobileTests/                 配置级 XCTest（校验 Info.plist 与模块注册，不断言渲染）
```

**启动在原生侧的样子**：`AppDelegate` 本体只管三件事——注册 TrackPlayer 生命周期观察者、存 launchOptions、WillResignActive 时补绘歌词卡片。真正的 bridge 创建在同文件的 `SceneDelegate`：先用 LaunchScreen 建窗防黑屏，`sceneDidBecomeActive:` 时单飞首次手动建 `RCTBridge` 并 `ReactNativeNavigation bootstrapWithBridge:`；冷启动 URL 先暂存再注入 launchOptions；`sourceURLForBridge` 优先包内 `main.jsbundle`、仅 DEBUG 回退 Metro。（JS 侧与之衔接的抢注逻辑见 [02 章](02-启动流程与运行时.md)。）

**音频会话不在 AppDelegate 统一管**：类别设置在 `StreamingFlacPlayerModule.prepareAudioSession`，激活散见于遥控入口与 NowPlayingModule——找音频会话问题不要只翻 AppDelegate。

JS 封装层的共同风格：每个 `nativeModules/*.ts` 都做能力探测与降级（如 appRestart 回退 DevSettings、userApi 有纯 JS 回退实现），业务层只 import 封装。**但降级不总是等价**，见 8.5 第 7、8 条。

## 8.3 三个最值得单独理解的原生机制

### 锁屏歌词时钟：为什么不用 NSTimer

`NowPlayingModule.setNowPlayingLyrics` 接收整条歌词时间轴后，原生侧用 **GCD dispatch_source 以 0.12 秒节拍 + 锚点外推 + 二分查行**推进锁屏歌词（`LXStartNowPlayingLyricTimer`）。原因：控制中心盖住 App 时主 RunLoop 退到非 common 模式，JS 定时器与 NSTimer 全部停摆——歌词会冻住。配套的还有屏幕亮度启发式 `LXScreenIsOn`：宁可多耗一点电，也不让歌词冻结。

### 媒体卡片强制重绘：翻转 playbackState

iOS 的 Now Playing 卡片有时不按预期刷新。原生侧的做法是把 playbackState 切反再切回强制重绘（`LXPerformNowPlayingCardRepaintFlip`），并设 1200ms 静默窗（`LXNowPlayingRepaintQuietWindowMs`）防止翻转期间用户的按键被发成反向命令。蓝牙路由时还会对调 title/artist 字段（`LXApplyNowPlayingTitleArtistFields`），让只读 title 的车机能显示歌词行。这些都是「与系统行为搏斗」的代码，改动前先读注释。

### TabBar 收起：Swizzle 全局滚动

Tab 收起态不靠各列表接线：`LXTabBarCollapseSetup` 在 `+load` 里直接 `method_setImplementation` 替换 `-[RCTScrollView scrollViewDidScroll:]`，在原生侧做迟滞状态机，全 App 列表零接线；状态经通知 → UtilsModule 的 `tabBarCollapseChanged` 事件才过桥到 JS（`utils/tabBarCollapse.ts` 消费）。

## 8.4 JS 工具层（`src/utils/`）速览

工具层是 JS 侧的平台适配与公共能力层。与原生最相关的几件：

- `fs.ts` 只有一行 `export * from './fs.ios'`（对齐 tsc 与 Metro 解析）；`fs.ios.ts` 是 RNFS 适配层：路径归一、读写/移动、gzip（pako）、`downloadFile`、`selectFile/selectFolder/shareFile`（桥 FilePickerModule）、`getWebDAVPrivateDirectory`。
- `request.js` 是全局 HTTP 层：fetch + `BackgroundTimer` 超时（普通定时器后台会冻结）+ AbortController，导出 `httpFetch/httpGet/checkUrl`。注意它夹带音源私有协议处理（对名为 `bHh` 的 header 做 hex 解码 + deflateRaw + base64 拼签名字段、按域名自动注入 wy/tx Cookie），细节属 musicSdk 范畴（04 章）；且 `fetchData` 会 console.log 请求体前 200 字符——排障方便，但有信息外泄面，勿在敏感请求上沿用。
- `data.ts`（772 行）是全 App 持久化门面：歌单位置/搜索历史/歌词/播放历史/同步主机/用户 API/每日推荐缓存的 get/save 全套 + `cleanOneDriveDirtyData`（键总账在 03 章）。子目录 `utils/data/` 有 `download.ts`（下载任务持久化与三种归一化）、`playlistIndex.ts`（我的歌单索引缓存，按 source 分键、loginKey 防串号）、`songlistDetail.ts`（歌单详情全量缓存，complete 标记是否拉全）。
- `listManage.ts` 是歌单内存态的操作集：**原地 splice 保引用**（07 章讲过引用相等对列表渲染的意义），并提供 `applyListOperation`——WebDAV 同步的操作队列重放就是调它（06 章）。
- `localLibrary.ts` 本地库目录语义（music/lrc/picture）：`findPictureForAudio`、`findLyricForAudio`、`cacheCoverToLibrary`、按 UTF-8 字节截断文件名。
- `localMediaMetadata(.ios).ts` 平台双实现：iOS 版优先原生 LocalMediaMetadata。
- 日志门面分工：`log.ts`（错误日志落盘 Caches/error.log，5MB 截断）、`bootLog.ts`（启动期内存缓冲，init 失败排查看它）、`playerLog/preloadLog/searchLog/txLog.ts`（同构分类门面，各自有开关设置键）、WebDAV 的 `webDAVLog`（05 章）。
- `tools.ts`（804 行）杂项大杂烩：`toast`、权限检查、`confirmDialog`、`handleSaveFile`（gzip+JSON）、`throttleBackgroundTimer/debounceBackgroundTimer`（后台也能跑的定时器）、`toMD5` 等。
- 其余纯函数与 hooks：`common.ts`（throttle/debounce/编辑距离 similar/文件名过滤等）、`withTimeout.ts`（02 章的超时回退就是它）、`windowSizeTools.ts`、`landscapeLayout.ts`（长边 ≥1000pt 为 iPad 档）、`hooks/`（`useHomeLazyPage`、`useHorizontalMode` 宽高比 >1.2 判横屏、`useDrag`、`usePhantomScrollGuard` 等；barrel 只收录 9 个、其余直引；`usePlayTime.js` 整文件被注释）。
- vendored 的 `simplify-chinese-main/`（MIT）：实际只导出 `tranditionalize`（简→繁查字表），经 `utils/index.ts` 以 `langS2T` 转出；其 `.d.ts` 声明的 `simplify` 在实现里被注释，类型与实现不一致。

## 8.5 原生层的设计与坑（代码证据）

1. **FLAC 能力靠搜索路径「点亮」，失败静默**：`AppDelegate.mm` 开头用 `__has_include(<FLAC/stream_decoder.h>)` 定义 `LX_HAS_LIBFLAC`；Podfile post_install 的注释直言：头搜索路径没加上则宏为 0、「FLAC 播放静音」且**编译不报错**。遇到「FLAC 没声音先查 Podfile 路径」。
2. **系统面板与 RN Modal 的竞态被当一等公民**：`FilePickerModule.presentDocumentPickerWhenReady` 轮询 40×50ms，等 RN Modal 的 window 消失才 present 系统文件选择器，另有孤儿 picker 检测与 `LXEnsureKeyWindow()` 恢复——注释称源于真机「选完文件整屏卡死」。
3. **加密双实现语义不一致**：原生 CryptoModule 是真 RSA/AES；而纯 JS 回退 `userApiFallback.ts` 把真实 `Buffer` 注入沙盒全局、`randomBytes` 用 `Math.random()`、`md5` 是 `stringMd5(encodeURIComponent(str))`；原生侧 `user-api-preload.js` 的 `randomBytes` 同样是 `Math.random()`。即用户脚本沙箱**并非真隔离**、且两条路径的加密语义/强度不同——涉及安全判断时以原生实现为准，不要拿回退实现的行为推断原生。
4. **同名双实现靠平台后缀分流、口径不一致**：`localMediaMetadata.ts` 的 `scanAudioFiles` 认 10 种扩展名，`.ios.ts` 版只认 audio/* mime 或 ogg；`.ios.ts` 在无原生模块时读造假元数据、**写静默 no-op**——「写标签成功」可能是假成功，调用前先查 `isWriteSupported()`。
5. **桥修复漏推事故（流程教训）**：AppRestartModule 的 `@property bridge + @synthesize` 修复 2026-10-24 写好，却两度不在推送清单里、随包未生效，直到 10-25 随提交 `1e66a7b1` 补推。教训已固化为流程：推送前逐项核对预期文件清单与 commit 文件清单（10 章）。
6. **entitlements 为空 + ATS 全开 + 文件共享全开**：`LxMusicMobile.entitlements` 是空 dict（无 App Group 等能力），数据只能走沙盒内路径交换——`FilePickerModule` 因此硬校验目录必须在 Documents 内、拒 `folder_outside_sandbox`；Info.plist 的 ATS `NSAllowsArbitraryLoads=true` 无例外表，全部音源的 http 明文被系统允许（安全口径如实记录，见 09 章配置要点）。
7. **持久化节流丢尾**：`data.ts` 大量落盘走 `throttle(..., 1000)` 且是节流非防抖，进程被杀会丢最后一截变更；同文件注释自承大歌单整表 `JSON.stringify` 会阻塞 JS 线程，「仅标注，暂不改」。
8. **测试与实现脱节一例**：`LxMusicMobileTests` 断言 UtilsModule 存在 `getWindowSize` 选择子，但 AppDelegate.mm 全文 grep 无此方法——测试过期还是方法被删，本轮未深追，如实标注。
