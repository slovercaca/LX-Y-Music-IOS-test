# 09 · 构建发布与工程配置

> 本章讲怎么把这个项目构建成 IPA、怎么发版、工程配置里有哪些不能乱动的东西。先给结论：**本地不构建 iOS**（开发机是 Linux），全部走 GitHub Actions 云端；产物是**未签名 IPA**，用户侧载时自签。

---

## 9.1 CI 工作流总览（`.github/workflows/`，5 个）

| 工作流 | 触发 | 做什么 |
|---|---|---|
| `build-test.yml` | PR → dev | ubuntu-latest + Node 20，只跑 `npm run lint` + `npm run build-test`（RN bundle 出 `ios/main.jsbundle` 验 JS 可打包）；不编译原生、无产物 |
| `ios-ipa.yml` | push 到 `master`/`ios-adaptation`、push `*-v[0-9]*` 格式 tag、手动 | 核心构建 + 双轨发布（见 9.2） |
| `ios-runtime-debug.yml` | push → ios-adaptation、手动 | 模拟器运行时冒烟（见 9.3） |
| `publish-version-info.yml` | release published、手动 | 不构建：仅用 repository-dispatch 向 `lyswhut/lx-music-mobile-version-info` 派发 `npm-release` 事件（上游版本信息体系） |
| `symbolicate.yml` | 手动 | 崩溃堆栈符号化：输入堆栈（+可选 run_id），无 run_id 时取最近成功的 iOS IPA 构建，下载其 sourcemap artifact 后 `npx metro-symbolicate` 还原 |

## 9.2 核心构建 `ios-ipa.yml`（172 行）

- 环境：runner `macos-26`（需要 Xcode 26 / Swift 6.2 才能编译 iOS 26 的 `UIGlassEffect`）；Node 按 `.nvmrc`；Ruby 3.2；`NO_FLIPPER=1`；Bundle ID `com.LX-YMusic.shuhao`；`concurrency: cancel-in-progress`；`contents: write`。
- 步骤：`npm install`（自动跑 postinstall 的 `dependencies-patch.js`，见 9.4）→ `gem install cocoapods ~>1.15` + `pod install --repo-update`（最多重试 3 次）→ 版本号取构建时刻 `date +%Y%m%d%H%M`（分钟级，同时用作 MARKETING 与 CURRENT_PROJECT_VERSION）→ `xcodebuild Release -sdk iphoneos CODE_SIGNING_ALLOWED=NO` 无签名构建 → 上传 sourcemap artifact（构建失败时另传 xcodebuild.log 并打印前 120 行 error）→ `.app` 入 `Payload/` 打成 `LX-Y Music-v<时间戳>-ios-unsigned.ipa` 并上传 artifact。
- **双轨发布（同一 job 按 ref 分流）**：
  - **分支 push → 滚动版**：`gh release upload latest --clobber` 覆盖 tag 为 `latest`、标题「Latest Unsigned Build」的 prerelease（不存在则 create）。注释注明弃用 softprops/action-gh-release——它在 Node 24 下大文件 content-length 不匹配。日常 push 后用户从这个 Release 下载最新构建。
  - **tag（且含 `-v`）→ 正式版**：IPA 改名为 `LX-Y-Test.Music-<代号>-v<数字>.ipa`；draft 已存在则 upload 覆盖，否则 `gh release create --draft --generate-notes` 生成草稿。**CI 不自动正式发布**：由人在网页端编辑更新日志后手动 Publish。
- **符号化约定**：sourcemap 只随 Actions artifact 保存，`latest` Release 里只有 IPA 没有 map——线上崩溃要按 run 回 Actions 找对应 sourcemap，再跑 `symbolicate.yml`。

发版操作口径（与工作流实现一致）：正式版 tag 格式 `<代号>-v<数字>`（如 `Ocean-v1`）；每个 Release 写清更新内容；工作流文件由项目维护者在网页端上传维护。

## 9.3 运行时冒烟 `ios-runtime-debug.yml`

真机前唯一的自动化运行时门禁：macos-26 上以 iphonesimulator Release 构建，`simctl` 装到首台可用 iPhone 模拟器、启动、等 60 秒、截图 + 抓日志；日志命中 `###UNDEFINED_ELEMENT###`、`Element type is invalid`、`FATAL_DIAGNOSTIC`、`TypeError`、`ReferenceError` 任一关键字即 exit 1。

它与一个 JS 侧哨兵联动：`babel.config.js` 的首个内联插件把所有 `react/jsx-runtime` 导入改写为 `@/utils/jsxRuntimeProbe`（该文件自身除外），后者在渲染到 type 为 null 的元素时打出 `###UNDEFINED_ELEMENT###` + 堆栈——把「undefined 组件」这类真机上静默白屏的问题变成 CI 可捕获的日志。注意此工作流的 CocoaPods 固定 1.12，与 `ios-ipa.yml` 的 ~>1.15 不一致（历史遗留，如实记录）。

## 9.4 依赖补丁体系（这个项目不用 patch-package）

原生音效等能力靠 **`dependencies-patch.js`（1161 行）在 `npm install` 的 postinstall 时自动织入**：对依赖做幂等的字符串替换，目标几乎全是 fork 钉死 commit 的 `react-native-track-player`。九组补丁：

1. **生命周期广播**（RNTrackPlayer.swift）：新增 `LXTrackPlayerLifecycle` 通知，在 destroy/reset/seek/stop/状态变化后广播 state/position/track/error，供主工程原生侧订阅（统一播放引擎的 TrackPlayer 驱动就靠它，见 [04 章](04-播放核心与音乐数据.md)）。
2. **能力去重**：删上游自动的 `play+pause→togglePlayPause` 逻辑，防遥控命令重复注册。
3. **均衡器接入 → 全音效引擎**：先加 `equalizerEnabled/Gains` + 挂 AVAudioMix，后重构为统一 `LXSoundEffectConfiguration` + `refreshSoundEffectAudioMix()`（强制主线程调度、切歌清旧 item 的 audioMix）；脚本里保留多轮迭代的中间态替换对。
4. **混音策略修复**：`setCategory` 仅在未请求 `.mixWithOthers` 时用 longForm，否则 default（注释直言 longForm 会忽略混音选项、使「关闭自动暂停」失效）。
5. **seeked 事件**：新增 `handleAudioPlayerSeekCompleted`，发 lifecycle `seeked`（真实落点）与 JS `player-seeked` 事件，供歌词精确重锚。
6. **中断结束不吞事件**：音频中断 `.ended` 时 options 缺失由 guard return 改 `?? 0` 照常发事件、恢复与否交 JS 决定（注释标注为 2026-10-03 车机蓝牙事故成因之一）。
7. **podspec 与桥接头**：podspec 的 source_files 扩入 `.mm`；桥接头加 `#import "LXSharedIRConvolutionBridge.h"`。
8. **SwiftAudio seek 修复**（正则版）：重写 `AVPlayerWrapper.seek(to:)` 为零容差 seek + 落点偏差 >0.2s 重试一次。**同一逻辑在 Podfile 的 `lx_patch_swift_audio_seek` 里还有一份**；Podfile 另有 `lx_patch_swift_audio_player_access` 给 QueuedAudioPlayer 注入 `currentPlayerItem`，是前者的跨文件依赖。
9. **整文件注入**（ensureFileContent）：把 `patches/ios/LXEqualizerAudioMix.swift`（1384 行完整原生 DSP 音效引擎：10 段 biquad EQ、相位声码器变调、峰值限幅、空间声像、卷积混响，经 MTAudioProcessingTap 挂 AVAudioMix）、`patches/ios/LXSharedIRConvolutionBridge.h/.mm` 与主工程的 `LXSharedIRConvolutionKernel.hpp` 复制进 track-player 的 Pod 目录随其编译——`patches/` 目录里的文件是**事实源文件、不是 diff**，靠这一步生效。

**Podfile 侧**（`ios/Podfile`）：platform iOS 14.0；target 构建前先现编 libFLAC 的 xcframework（失败 raise 中止）；本地 pod 三个（LXLibFLAC、SwiftAudioEx、LiquidGlassKit）；post_install 给 SwiftAudioEx 打两处源码补丁（上第 8 条）、全 Pods 部署目标强制 14.0、给主 target 追加 LXLibFLAC 头搜索路径（缺了它 FLAC 会静默失效，见 [08 章](08-原生层与桥接模块.md) 8.5 第 1 条）。

**脆弱点（如实记录）**：`patchFile` 的字符串锚点对不上时**静默跳过**（只有 regex 版抛错）——升级或换源安装 track-player 可能出现「装成功了但功能没进去」；SwiftAudio seek 修复双份存放，改一处必须同步另一处。

## 9.5 契约脚本（`scripts/`，实测 44 个）

这个项目的回归防线主要不是单测，而是 `scripts/` 下的源码级契约/状态机复刻脚本：不启动 App、只读源码或复刻状态机做断言，退出码 0/1。其中 `check-*` 2 个、 `sim-*` 41 个、`.ps1` 1 个。

- `check-i18n-keys.js`：所有 `t('…')` 字面量必须在 zh-cn.json 有词条。
- `check-sound-effect-dsp.js`：音效 DSP 的单一事实源 `config/soundEffectDspProfile.json`（EQ 频点/Q、限幅阈值、变调范围、声码器 block/hop、processingOrder）必须与 AppDelegate 与 Swift 两处原生实现逐值一致（以 lint script 形式暴露）。
- `embed-liquid-glass-shaders.ps1`：把 Metal 着色器嵌入为 Swift 常量（硬编码 Windows 路径，仅本地维护用）。
- 41 个 `sim-*` 各守一条真机教训，举例：`sim-seek-sync-matrix`（双引擎全音质 seek 同步矩阵）、`sim-remote-command-single-source`（遥控命令单通路 + 切歌去重）、`sim-nowplaying-elapsed-regress`（已播放时间外推倒退）、`sim-glass-contrast`（玻璃底衬三层对比度模型）、`sim-songlist-detail-page-crash`（歌单详情分页切分根因复刻）、`sim-webdav-page-contract`（WebDAV 页结构契约）、`sim-startup-autoplay`（启动自动播放仅限恢复歌曲为暂停态）。

**重要事实：这 44 个脚本无一被任何 workflow 调用**，`build-test.yml` 也只跑 lint + bundle。防线强度取决于本地执行纪律——改到对应区域时，先在 scripts 里找有没有守它的脚本，有就跑一遍再提交。

## 9.7 构建排障速查

- **JS 改动想快速验**：本地跑 lint / 转译检查即可；bundle 级验证看 `build-test.yml` 的结果。
- **原生改动**：只能等 `ios-ipa.yml` 或 `ios-runtime-debug.yml` 的云端结果；构建失败先看工作流上传的 xcodebuild.log 前 120 行 error。
- **装完依赖功能缺失**（音效/生命周期事件不工作）：先怀疑 9.4 的补丁没打上——重跑 `node dependencies-patch.js` 并检查锚点是否命中。
- **FLAC 静默无声**：查 Podfile 的 LXLibFLAC 头搜索路径（08 章 8.5 第 1 条）。
- **崩溃堆栈看不懂**：用 `symbolicate.yml`，记得选对 run_id 的 sourcemap。
