## 7.2 Home 页内部结构

### 骨架与页面集

- 竖屏骨架 = `Vertical/Content`（页头 + `Main` + `ModernTabBar`）+ 绝对定位悬浮的迷你播放器 `PlayerBar(isHome)`。多数页面用通用 `Header` 显示 `t(navId)` 大标题，但 `PAGE_OWNED_HEADER_IDS` 里的页面（discovery/search/love/top/每日推荐/平台歌单等）自接管页头，骨架不渲染。
- 底部 `ModernTabBar` 只有 **5 个 tab**（推荐/发现/搜索/我的/设置）；其余页面从发现页功能网格等入口进入。
- 页面集由 `src/config/constant.ts` 的 `NAV_MENUS` 定义，共 **17 个 nav id**：

| nav id | 页面 | nav id | 页面 |
|---|---|---|---|
| `nav_discovery` | 推荐（发现） | `nav_my_playlist` | 网易我的歌单 |
| `nav_search` | 搜索 | `nav_tx_playlist` | QQ 我的歌单 |
| `nav_play_history` | 播放历史（覆盖层，见下） | `nav_kg_playlist` | 酷狗我的歌单 |
| `nav_songlist` | 歌单广场 | `nav_followed_artists` | 关注歌手（网易） |
| `nav_top` | 排行榜 | `nav_subscribed_albums` | 收藏专辑（网易） |
| `nav_love` | 我的列表 | `nav_webdav` | WebDAV 音乐库（05 章） |
| `nav_daily_rec` | 网易每日推荐 | `nav_local_download` | 本地下载 |
| `nav_tx_daily_rec` | QQ 每日推荐 | `nav_setting` | 设置 |
| `nav_kg_daily_rec` | 酷狗每日推荐 | | |

- **可见集三重过滤**：设置 `common.navStatus`（显隐）× `common.navOrder/navFlatOrder`（经 `getEffectiveFlatOrder` 算有效顺序）× 登录门控 `NAV_COOKIE_GATED_IDS`（wy/tx/kg 的我的歌单、关注歌手、收藏专辑须有对应平台 Cookie 才出现）。

### 切换机制与保活

- `Vertical/Main.tsx` 用一个 `scrollEnabled=false` 的 `PagerView` 装全部可见页，切换靠 `setNavActiveId()` 下发 `setPageWithoutAnimation`——没有手势翻页，PagerView 在这里只是个保活容器。
- 多数页经 `useHomeLazyPage(navId, factory)` **首次激活才挂载**，之后保活。两个例外：排行榜与设置页**离开即卸载**（监听 `navActiveIdUpdated` 自行置空；注释说明排行榜无须跨页保状态、设置可由持久化恢复）。
- 播放历史不是 PagerView 的一页，而是覆盖层 `PlayHistoryOverlay`：显示时把 PagerView 设 `opacity: 0`（不卸载）以透出背景层防闪白。
- 横屏 `Horizontal/Main.tsx` 不用 PagerView，按当前 navId 以 switch 渲染单页；已做横屏分栏的页面（清单在 `FULLWIDTH_LANDSCAPE_IDS`：排行榜、设置、我的列表、歌单广场、平台歌单、搜索、本地下载等）铺满右栏，其余竖屏页用 `LandscapeCentered` 限宽居中。

### 各 Views 一句话

`Discovery` 发现页（平台 chips + 每日推荐卡 + 歌单横架 + 榜单入口，数据走 `core/songlist` / `core/leaderboard` 第一页 + TTL 节流）；`Search` 搜索（联想词、歌曲/歌单/歌手/专辑四类结果，空态含热搜与历史）；`Mylist` 我的列表（见下）；`SongList` 歌单广场（平台/排序/标签三行筛选 + 自适应网格，列数取 `theme.songlistColumns`）；`Leaderboard` 排行榜（横竖双实现共用 `MusicList`，状态持久化）；`DailyRec / TXDailyRec / KgDailyRec` 三平台每日推荐（网易版另有风格化推荐 `StylizedModal`）；`MyPlaylist / TxPlaylist / KgPlaylist` 三平台「我的歌单」（created/collected 双页签，走 `core/playlistIndex`，与本地的 Mylist 是两回事）；`FollowedArtists / SubscribedAlbums` 网易关注歌手/收藏专辑（薄页，数据进 `store/user`）；`PlayHistory` 播放历史（按日/区间查 + 自带日历弹窗）；`LocalDownload` 本地与下载（双标签：本地标签以磁盘扫描为准生成可播列表——扫到的文件按完整路径命中已完成任务时用任务信息展示，没扫到的下载记录不显示，含孤儿歌词/封面清理；下载标签分组管理全部下载任务）；`Download/index.js` 是仅 16 行的占位桩，无逻辑。

### Mylist 内部

`index.tsx` 固定转发 `NewListUI`（旧抽屉 UI 已删）：固定卡（默认/收藏）与用户歌单同列一个 FlatList，长按拖拽排序落库 `core/list.updateUserListPosition`；点卡后横屏同屏、竖屏以覆盖层打开歌曲层 `MusicList/`（`List` 监听 `myListMusicUpdate` 增量更新、滚动位置按列表持久化、多选经 `MultiSelectTopBar`、单曲菜单动作集中在 `MusicList/listAction.ts`）；歌单层操作（新建/重命名/排序/查重/导入导出 `.lxmc`、同步源歌单）在 `MyList/` 子目录。

## 7.4 播放详情页（PlayDetail）

**竖屏**：自上而下 `Header`（`components/HeaderNew`：返回、页指示点、定时退出、设置入口）→ 两页 PagerView → 常驻底部控制条 `Player`。第 0 页封面页、第 1 页歌词页。**进度条刻意放在 PagerView 之外**，避免拖拽 seek 与切页手势互相劫持；拖动期间经 `progressDragState` 事件 + `registerPager` 同步锁禁用横滑。

- **封面页**：`Pic`——封面用 `Animated.createAnimatedComponent(FastImage)` 直接承载旋转（包在 Animated.View 里 iOS 会白屏，注释有记）；旋转用手动启停的 timing 动画而非 `Animated.loop`，受设置 `playDetail.style.coverSpin`、形状 `coverShape`（圆形靠自身 `borderRadius = size/2`）、大小 `coverSize` 控制；长按弹 `CoverLongPressMenu`（下载歌曲/封面到系统相册）。下方 `components/SongInfo`（歌名/歌手/专辑 + 来源音质徽章 `SourceQualityBadge`）与 `components/MiniLyric`（上/当前/下三行歌词，点击切到歌词页；小屏 <700pt 降级只显示当前行）。
- **歌词页**：`Vertical/Lyric.tsx`，FlatList + `@/plugins/lyric` 的 `useLrcPlay/useLrcSet` 驱动高亮行与 rAF 平滑滚动；逐字歌词行渲染 `components/KaraokeLyric`（自带 rAF 按音频时钟算当前字，仅本组件重渲染）；歌词页**始终预挂载**、`active` 只控制滚动定位，避免首次滑入时集中渲染卡顿；仅歌词页保持屏幕常亮（评论页打开时释放）。
- **控制区**：`PlayerNew` = `PlayInfo`（进度条 + 时间）+ `ControlBtnNew`（播放模式/上一首/播放暂停/下一首/队列）+ `FeatureBtns`（喜欢、下载、评论、更多菜单 `PlayDetailMenu`、相似歌曲、加歌单等）；播放模式切换逻辑在 `components/usePlayModeToggle`；头部设置按钮打开 `components/SettingPopup`（音量、倍速、音效入口、歌词字号/对齐、迷你歌词对齐、封面旋转/形状/大小），音效另有 `components/SoundEffectPopup`；队列面板经全局事件 `showPlaylist` 命令式弹出。

**横屏**：左右分栏——左栏（`useLandscapeLayout` 算比例）自上而下 Header、`MoreBtn`（播放模式/定时退出/加歌单/下载）+ Pic、Player；右栏整块 Lyric；播放详情全程保持屏幕常亮（进后台或打开评论页时释放）。

## 7.5 主题机制与液态玻璃

### 主题：单主色程序化生成整套色板

- `src/theme/themes/createThemes.js` 是 **Node 构建期脚本**：内置 **16 套主题**（绿意盎然、蓝田生玉、蛋雅深蓝、橙黄橘绿、泥牛入海、热情似火、粉装玉琢、重斤球紫、灰常美丽、青出于黑、清热板蓝、黑灯瞎火（唯一深色）、月里嫦娥、木叶之村、近墨者黑、新年快乐），每套只写 `primary`、`font` 与少量扩展键。
- `themes/utils.js` 的 `createThemeColors(primary, font, isDark)` 用 `colorUtils.js` 的 pSBC 微函数迭代生成 `c-primary-dark/light-100…1000`、各档 alpha 变体与字体灰阶 `c-050…c-1000`；脚本把结果写成**生成文件** `themes.ts`（4050 行，文件头注明由 createThemes.js 生成）——运行时直接 import，不再现场生成。**改主题色板要改 createThemes.js 再跑脚本，不要手改 themes.ts**。
- 运行时装配在 `src/theme/themes/index.ts` 的 `buildActiveThemeColors(theme)`：把色板与扩展键合并成 `LX.ActiveTheme`，先解一层 CSS 式 `var(c-xxx)` 引用（扩展键如 `c-app-background: var(c-primary-light-600-alpha-700)`），再派生语义色（`c-font`、`c-primary-background`、`c-button-*` 等）。自定义主题（`isCustom`，经 `getAllThemes/saveTheme/removeTheme` 存取于 utils/data 的 userThemes，背景图在 `theme_images/` 目录）与内置图主题（`BG_IMAGES` 映射 `images/` 下 5 张打包图）分别处理背景图路径；设置 `theme.cardOpacity` 会在此处用 `withAlpha` 直接改写两档半透明底色的最终 alpha。
- 主题选择 `getTheme()`：跟随系统深色（`common.isAutoTheme`）或手动深色（`common.isDarkMode`）时强制用唯一深色主题 `black`，否则用 `theme.id` 选定主题，找不到回退 `green`。
- 生效链路：`core/init/theme.ts` 启动 `applyTheme(await getTheme())` 并监听系统外观变化 → `store/theme/action.ts` 的 `applyTheme` 调 `buildActiveThemeColors` 写 theme store → 组件统一 `useTheme()` 取 `LX.ActiveTheme` 拼样式；`themeUpdated` 事件同步状态栏明暗。
- 另有静态设计令牌 `src/theme/DesignTokens.ts`（spacing/radius/typography/motion，其中 `designRadius.glass = 28` 是玻璃胶囊统一圆角）与近似遗留的 `Colors.js` / `Typography.js`（经 `theme/index.js` 导出，未见与主色板联动）。

### 页面背景（`components/PageContent.tsx`）

所有页面的背景层：背景图来源优先级 **自定义背景 > 动态背景（当前歌曲封面）> 主题 `bg-image`**；模糊走原生预模糊缓存图（`useBlurredPic`）优先、RN `blurRadius = theme.blur` 回退，其上叠平均色底与 `theme.picOpacity` 透明度；PlayDetail 用 `backgroundFadeIn` 做 350ms 淡入。

### 液态玻璃：vendored 原生 Metal 组件，不用任何 BlurView 库

- JS 侧 `common/LiquidGlass.tsx` 以 `requireNativeComponent('LiquidGlassView')` 封装 vendored 的 **LiquidGlassKit**（`ios/Vendor/LiquidGlassKit/Sources/`，Metal shader 实现折射 + 边缘光 + 逐帧背景捕获，原生细节见 [08 章](08-原生层与桥接模块.md)）。
- 双形态：`liquid = true` 走 Metal 液态玻璃；否则走系统材质（iOS 26+ 为 `UIGlassEffect(.regular)`、其余 `UIBlurEffect(.systemMaterial)`）加中性染色覆层。
- 分层封装：`common/GlassSurface.tsx` 是浮层总容器（自读 `theme.glassOpacity / theme.liquidGlass / isDark`，并**主动剥离调用方 `style.backgroundColor`** 防挡折射），`Dialog/Popup/Menu` 等浮层用它；`common/ContentGlass.tsx`（内容卡片，受 `theme.glassContent` 开关）与 `common/UtilityGlass.tsx`（浮动工具，受 `theme.glassUtility`）在关开关时回退普通 View + `fallbackBackgroundColor`；`common/LiquidLens.tsx`（原生 `LiquidGlassLens`）是 TabBar 的选中药丸：静止为半透白药丸，切 tab 时原生弹簧滑动、挤压拉伸并 morph 成液态玻璃。`ModernTabBar` 与 `PlayerBar` 直接消费 `LiquidGlass + LiquidLens`。
- **版本门控**：iOS 26.2+ 因原生液态分支闪烁，`LiquidGlass.effectiveLiquid` 与各消费点三重强制 `liquid = false` 走磨砂，设置页亦隐藏液态开关。
- **省电**：`paused` prop（由 `useHomeCovered/useScreenCovered/useAppActive` 判定）让被压栈覆盖/进后台时暂停 Metal 逐帧渲染。
- **可读性保底**：深色模式下磨砂覆层 alpha 有下限（`DARK_OVERLAY_FLOOR_USER = 0.2/0.6`）；tab 未选中文字色用经对比度脚本验证的 `TAB_INACTIVE_LIGHT/DARK` 常量（`ModernTabBar.tsx`，与 `scripts/sim-glass-contrast.js` 人工同步）。

## 7.6 多语言机制

- 组织：`src/lang/index.ts` 维护 `langs` 注册表并汇总 `messages` 与 `langList`；文案是平铺 JSON（`src/lang/zh-cn.json`，814 行，键如 `setting_basic_lang`、`nav_discovery`——**导航 id 本身即文案键**）。`src/lang/Readme.md` 列了 38 个预定 locale 代码，但**当前只注册了 `zh_cn` 一种**；设置页在 `langList.length <= 1` 时直接显示「目前仅提供简体中文」。
- 运行时：`src/lang/i18n.ts` 的 `createI18n()` 造单例 `global.i18n`，`fallbackLocale = 'zh_cn'`；`getMessage(key, val)` 先查当前语言、缺失回退中文、再缺失返回空串；`fillMessage` 做 `{key}` 占位替换（用函数式 replacer，防歌名里的 `$$/$&` 被当特殊模式展开）。组件侧 `useI18n()` 返回稳定的 `t(key, val)` 并把自身注册进模块级订阅表。
- 切换原理：`setLanguage(lang)`（经 core/common 包装后同时落设置 `common.langId`）更新单例并广播，所有挂载中的 `useI18n` 组件以 useState 触发重渲染，**无需重启**；启动定初始语言的顺序见 02 章步 4。

## 7.8 界面层的设计与坑（代码证据）

1. **PagerView 切页可靠性是系统性课题**（`Home/Vertical/Main.tsx`）：原生后台恢复后 `setPage*` 会变空操作、偶发丢弃切换无回执。JS 侧三级防线：以原生回执 `observedIndexRef`（区别于乐观写入的 `activeIndexRef`）判落点、400/900ms 重试链、仍失败则 `repairPager` 换 `key` 重建整个 PagerView（会话上限 `MAX_PAGER_REBUILDS = 3` + 3 秒防抖）；另有 `homePagerIdle` 800ms 兜底恢复（idle 事件丢失会让列表点击被静默吞掉）、页面集变化时以 `pagerKey` 整体重建避 iOS 原位重排崩溃。
2. **列表原地变更 vs React 引用相等**：多处自维护镜像 + 版本号逼重算——`Mylist/MusicList/List.tsx` 的 `listVersion`、`OnlineList/List.tsx` 的 `lastSetListRef/listVersion`（防 `setList ↔ onListUpdate` 回环把列表刷得只剩 12 条）、`SonglistDetail/MusicList` 要求 `songlistState.listDetailInfo.list === fullListRef` 同引用否则下标错位静默不播；`ArtistDetail/SongList.tsx` 的 `lastSyncedListRef` 专门阻断同类回环。
3. **分页竞态一律用 ref 不用 state**：`ArtistDetail` 的 `songsRequestIdRef`、`Comment` 的 `requestSeqRef`——注释均指明 iOS `onEndReached` 连发 + state 同帧不可见会并发覆写。
4. **命令式组件两种范式并存**：弹层/弹窗普遍 `forwardRef + Type.setVisible/show()`；五个登录/选择 Manager（`WebLoginManager` 等）是**事件驱动懒挂载宿主**——订阅 `global.app_event` 的字符串事件（`'showWebLogin' as any` 等）首次触发才挂载真身，调用方只能发事件，耦合点在全局总线上。完整挂载清单本轮未全确认（已确认 Home 挂 ArtistSelectorManager、SettingDetail 挂三家登录 Manager）。
5. **`createStyle` 返回数字注册 ID**：`GlassSurface.tsx` 的 `safeStyle` 必须用 `StyleSheet.flatten` 展平后再剥 `backgroundColor`，手动 `{...123}` 解构会把样式丢光（P1-1 修复）；`Main.tsx` 的 PagerView 亦有同类防线。
6. **玻璃染色必须先 `processColor`**：`LiquidGlass.tsx` 的 `nativeTint`——`tint` 传 rgb() 字符串原生会静默转 nil、染色永不生效（注释记载曾踩坑），与 [05 章](05-WebDAV子系统.md) 的 `new URL()` 同属「Hermes/桥接层的静默失败」家族。
7. **平台能力不对齐靠隐藏兜底**：三详情页 `getApi()` 未知源回退 wy；收藏/关注/发评仅网易实现，tx/kg 靠在 `AlbumDetail/Header.toggleSubscribe` 等处以条件判断隐藏按钮；`Comment/utils.sendComment` 直接写死 `music.wy.comment.*`。
8. **拼写固化成公共 API**：`common/DorpDownMenu.tsx`、`DorpDownPanel/`（应为 Drop）、`OnlineList/List.tsx: onMuiltSelectMode`（应为 Multi）、`Mylist/MusicList/index.tsx: hancelExitSelect`（应为 handle）——改名即破坏调用方，grep 时也要按错拼搜。
9. **死代码与复制痕迹**：`SonglistDetail/Header.tsx` 默认导出疑似旧版遗留（是否仍被其他入口引用未全仓确认）；`SimilarSongs` 的 `OnlineList listId='dailyrec_wy'` 与播放 id 不一致，疑从每日推荐复制；`CommentHot/CommentNew` 约 150 行近逐行重复未抽 hook；`Progress.tsx` 与 `ProgressBar.tsx` 渲染层重复实现；`MusicAddModal` 与 `MusicMultiAddModal` 近克隆（批量版壳还误导出单曲版同名 props 类型 `MusicAddModalProps`）。
10. **被注释掉的设置开关曾造成死锁**：「键被同步/备份写坏后界面无处可改」——三处已补回并留注释：`Setting/settings/Download/index.tsx: IsEnable`、`Basic/index.tsx: IsStartupPushPlayDetailScreen`、`Player/index.tsx: IsShowNotificationImage`。
11. **componentId 登记口径不一**：`AlbumDetail` 用枚举 `COMPONENT_IDS.ALBUM_DETAIL_SCREEN`，`ArtistDetail/SimilarSongs` 用字符串字面量 `as any`，易漂移；`SonglistDetail` 注释记载漏登记曾导致新页压错栈。
12. **图标字体缺陷绕行**：`common/Icon.tsx` 的 `HEART_NAMES` 拦截 `love/love-filled` 改走 SvgIcon，因 IcoMoon 字形越界在 iOS 渲染成红框问号。
13. **安全提示**：`KgWebLoginModal.tsx: generateVerifyHtml` 把 `txappid/ssaCode` 直接模板拼进 HTML/JS 字符串，存在注入面（本轮未做利用验证，如实标注）。
