# 10 · 本分支二改说明

> 本章只写**代码与提交记录可证实**的二改内容：这个分支（`ios-adaptation`，工作代号 Sea）相对上游做了什么、为什么。上游基底是 `1970905901/LX-Y-Music-IOS`（其本身 fork 自 `Q-1515/lx-music-mobile` 的 iOS 适配），许可证 Apache 2.0（允许修改与再发布，须署名）。
>
> 仓库：`slovercaca/LX-Y-Music-IOS-test`；构建走 GitHub Actions 云端（见 [09 章](09-构建发布与工程配置.md)）；未签名 IPA 发布在 Releases 的「Latest Unsigned Build」。

## 10.1 二改全景

二改可以归成五条线：

1. **WebDAV 云盘曲库**（05 章）：从无到有的完整子系统——扫描建库、在线点播、批量上传队列、多服务器档案。
2. **WebDAV 数据同步**（06 章 A）：歌单/设置/音源三文件同步、操作队列重放合并、多服务器故障转移。上游只有 06 章 B 的同步服务器体系。
3. **液态玻璃 UI**（07 章 7.5）：vendored 的 LiquidGlassKit 原生 Metal 组件 + GlassSurface/ContentGlass/UtilityGlass/LiquidLens 分层封装 + ModernTabBar。
4. **本地库与离线体验**：下载目录三分结构统一、封面全局缓存、离线模式、本地下载页重做。
5. **海量稳定性修复**：2026-10 的全量审查（约 230 个文件）与后续多轮真机问题修复，很多已散落在各章的「设计与坑」里，本章 10.6 汇总索引。

## 10.2 WebDAV 云盘曲库（二改新增）

`src/core/webdavMusic/` 五个模块 + 原生上传模块 + 四个 Tab 的页面，整体见 05 章。几个只有二改者才知道的来历：

- 子系统最初是一个大文件 `drive.ts`，后拆为 client/files/library/upload 四个模块，`drive.ts` 保留为 re-export 兼容层让调用方零改动。
- 远端目录语义（music 与 lrc/picture 兄弟）与本地库三分结构是同一套约定，两边对齐后「下载到本地」与「服务器上的样子」可以一一对应。
- 原生上传模块 `WebDAVUploadModule.swift` 是为绕开 RNFS multipart 而写的 raw PUT；分块（Content-Range）与取消句柄都是它提供的能力。

## 10.3 WebDAV 数据同步（二改新增）

见 06 章 A。这里补三条演进史：

- **上传策略翻案过一次**：曾尝试用 MOVE 代替 DELETE-before-PUT（为绕开个别服务器对 DELETE 的 412），真机验证发现 MOVE 在 CloudDrive 上不可靠，已改回 DELETE 策略。这段历史解释了为什么 files.ts/upload.ts 的注释里同时留有 MOVE 与 DELETE 的讨论。
- **操作队列的快照清理**是被「同步收尾整表清空抹掉同步窗口内新编辑」的真机问题逼出来的（06 章 6.8 第 1 条）。
- **`sync.webdav.path` 参与档案切换**：早期档案没有 path 字段，老档案切换时保留当前 path 的兼容逻辑在 `profiles.ts`。

## 10.4 本地库、封面与离线（二改）

- **目录结构统一（2026-10）**：新建 `src/utils/localLibrary.ts` 统一目录语义：下载根目录下 `music/、lrc/、picture/`。启动时有一次性迁移（02 章 2.4 的 `initDownloadPath` 四步迁移）。
- **封面全局缓存**：下载完成自动缓存封面；在线封面改为本地缓存优先；新设置 `player.autoCacheOnlinePic`（默认开）。WebDAV 批量获取封面会上传到远端 `picture/` 并回写 `picPath`。
- **离线模式（2026-10）**：新设置 `player.offlineMode`，歌单顶部有切换按钮（组件 `OfflineModeToggle`）；开启后按 ID / 歌名+歌手匹配已下载文件，未下载的提示并自动跳过；封面优先用本地。
- **LocalDownload 页合并**：原多个列表合并为单一列表，删除歌曲连带删除同名 lrc/picture，另有「清理孤立文件」。
- **WebDAV 上传的父目录 409 处理**：远端父目录缺失返回 409 时，上传器弹窗询问后可自动建目录重试（05 章 5.4.4）。

## 10.5 播放与平台（二改增补）

- **播放历史子系统**（`core/init/player/playHistory.ts` + 播放历史页 + 按日/区间查询与日历弹窗）：注释注明为本项目独有，上游参考分支无此模块。记录口径：播放满 120 秒或比例过半才落一条（02 章 2.4）。
- **统一播放引擎层**（`src/plugins/player/engine/`）：在 TrackPlayer 驱动与原生 FLAC 驱动之上封一层统一事件总线（`UnifiedPlayerEventBus`）与统一状态枚举，iOS 上 FLAC 走原生驱动时屏蔽 TrackPlayer 生命周期事件（`shouldIgnoreTrackPlayerLifecycle`）。细节见 [04 章](04-播放核心与音乐数据.md)。
- **平台每日推荐与我的歌单**：QQ/酷狗每日推荐、QQ/酷狗「我的歌单」、网易关注歌手/收藏专辑等页面为二改扩充（07 章 7.2 的页面集）；导航的 Cookie 门控（没登录就不显示入口）也是配套设计。

## 10.7 二改的工程约定

- **改动流程**：本地改 → 自查（转译检查 + 人工复读作用域 + grep 全量引用点；转译检查只查语法、查不出跨组件作用域错误，有过 `descExpanded` 跨组件作用域崩溃的教训）→ 用户真机确认无 bug → 用户亲口说 commit → 一次 commit 推送 → 读回远端逐文件核对 blob SHA。
- **发版流程**：正式版 tag 格式 `<代号>-v<数字>`（如 `Ocean-v1`），IPA 文件名 `LX-Y-Test.Music-<代号>-v<数字>.ipa`；tag 触发构建 → 改名 → 建 draft Release（自动生成更新日志草稿，网页端编辑后手动 Publish）；日常 push 更新滚动的 latest 构建。
- **分支纪律**：所有改动只在 `ios-adaptation` 分支；工作副本 `LX-Y-Music-IOS-test-sea`（代号 Sea），旧副本（test-v2、fire）封存不动。

## 10.8 诚实边界

- 本章的二改归属以代码注释、提交历史（`36e2238b`、`fc60ff1d` 等）与本项目的工作记录为准；个别页面（如三平台每日推荐）的逐文件归属未做逐一考据，按页面集整体表述。
- 液态玻璃的 LiquidGlassKit 为 vendored 第三方原生代码（`ios/Vendor/`），二改在其上做的是 JS 封装、门控与消费点，不是玻璃渲染本身的作者。
- 上游 LX Music 桌面端/移动端的原始架构（事件中枢、store 三段式、musicSdk 多源体系）来自上游 lyswhut 等作者，二改是在其上增补与修复，本指南各章对上游原有部分同样如实描述、不冒领。
